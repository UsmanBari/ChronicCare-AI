# ChronicCare-AI: OCR Spike (Day 5)

This folder contains the independent research spike for Prescription and Lab Report Optical Character Recognition (OCR) for ChronicCare-AI.

## Architecture Boundary
- **Isolated Module**: This directory is completely isolated from production code. `backend-poc-technical/main.py` and existing agents NEVER import from `ocr_spike`.
- **Own Virtual Environment**: Uses its own isolated `.venv` (`backend-poc-technical/ocr_spike/.venv`) with separate `requirements.txt`.
- **Deterministic Synthetic Samples**: Synthetic medical documents generated by `generate_samples.py` with known ground truth in `samples/ground_truth.json`.

---

## 3 OCR Options Evaluated

### 1. Tesseract (v5)
- **Engine**: Classical OS-level OCR engine via `pytesseract`.
- **System Requirements**: 
  - Windows: UB-Mannheim installer (`https://github.com/UB-Mannheim/tesseract/wiki`). Check "Urdu" under additional script languages.
  - Linux / Debian: `apt-get install -y tesseract-ocr tesseract-ocr-urd`.
- **Render Free Tier Compatibility**: **NO**. The Render Native Python environment lacks `root` and `apt-get`. Running Tesseract on Render strictly requires a Docker environment (`Dockerfile`).
- **Memory Footprint**: ~30–70 MB.

### 2. EasyOCR
- **Engine**: Deep learning (CRAFT + CRNN) built on PyTorch.
- **System Requirements**: `pip install easyocr` (pulls `torch` and `torchvision`, ~1.5 GB disk).
- **Render Free Tier Compatibility**: **NO**. PyTorch + model weights consume 400–700 MB RAM during inference, exceeding Render's 512 MB free tier RAM ceiling (triggers OOM kill 137).
- **Memory Footprint**: ~400–700 MB.

### 3. Groq Vision (Hosted API)
- **Engine**: LLaMA 3.2 Vision (`llama-3.2-11b-vision-preview` / `llama-3.2-90b-vision-preview`) via Groq's high-speed inference engine.
- **System Requirements**: Pure Python `groq` client library (`pip install groq`). Requires `GROQ_API_KEY` in environment.
- **Render Free Tier Compatibility**: **YES**. Lightweight HTTP client consumes < 20 MB RAM on host. Compatible with Render free tier.
- **Privacy Trade-off**: Image leaves host server for Groq API processing; requires explicit patient consent before transmission.

## Running the Spike

### Step 1: Generate Synthetic Samples
```powershell
$env:PYTHONIOENCODING="utf-8"
python backend-poc-technical/ocr_spike/generate_samples.py
```
*Note: If `PIL.features.check("raqm")` is False, Urdu-script samples are skipped to prevent malformed disconnected text.*

### Step 2: Run Field Extractor Tests
Hermetic regex and dictionary parsing tests (HbA1c, Glucose, Blood Pressure, Medications):
```powershell
pytest backend-poc-technical/ocr_spike/test_extract_fields.py -v
```

### Step 3: Run Benchmark Comparison
```powershell
python backend-poc-technical/ocr_spike/run_compare.py
```
Outputs performance, memory, and status tables to stdout and updates `docs/ocr/compare_results.md`.
