## 3. Governing Clinical Decisions (D10 – D15)

1. **Decision D10 (Production Model Export and Runtime Format + Amendment):** Pure-Python export of Logistic Regression (unless a tree model beats it by $\ge 0.02$ validation AUROC). Calibration double-dipping avoided: secondary calibration on the validation set is removed, because the validation set is already used to pick the operating threshold. Calibration is only reported (slope/intercept). If the validation slope is outside $0.8-1.2$, Day 4 stops and asks Usman. **D10 AMENDMENT (29 Oct 2026):** Between `lr` and `lr_balanced`, choose plain `lr` unless `lr_balanced` beats it by $\ge 0.01$ validation AUROC, because class-balanced sample re-weighting inflates predicted probabilities and distorts probability calibration. Tree models remain unchanged (+0.02 rule over the chosen LR).
2. **Decision D11 (Minimum Acceptance Gates for FYP-1):** Modified 5 gates on the held-out temporal test set (`test` 2017-2023): (1) Test AUROC $\ge 0.75$ (report bootstrap 95% CI; CI is descriptive and not a gate), (2) Test Sensitivity $\ge 0.75$ at the locked validation threshold, (3) Calibration slope $0.8-1.2$, (4) Subgroup sensitivity $\ge 0.60$, (5) FULL beats BASIC. `diabetes_full_nhanes` passes all 5 gates and is classified as `SHIP CANDIDATE (all D11 gates passed)`. The other 5 models fail Gate 1 and/or Gate 4 and are `NOT SHIPPED`.
3. **Decision D12 (Diabetes Risk Deployment):** `diabetes_full_nhanes` is statistically a `SHIP CANDIDATE (all D11 gates passed)`, but its card-population AUROC is 0.6640. In FYP-1, it is displayed **ONLY on the provider review page** labeled: *"Experimental: trained on US NHANES data, not validated for Pakistani patients"*, behind the `RISK_ENABLED` feature flag (off by default in production, can be toggled on for demo). It is **NEVER shown to patients in FYP-1**. It requires `waist_cm`; without `waist_cm`, the provider sees "not enough information" (no fallback to basic, which failed its gates).
4. **Decision D13 (Hypertension Risk Deployment):** Retired for FYP-1. Card-population AUROC is ~0.54 (near chance), and in older adults (60+), the model flags 100.0% of individuals (specificity 0.0%), providing no discriminatory value. Artifacts and code are retained for documentation and academic reporting only.
5. **Decision D14 (Recommendation to Supervising Clinicians):** For patients with diabetes, ask for an actual blood pressure reading (or "when was your BP last checked?") instead of predicting high BP through demographic surrogates. Requires clinical approval before implementation.
6. **Decision D15 (Proposed Patient-Facing Feature / Screening Reminder):** A rule-based screening reminder (needs doctor approval; NOT built today). If a patient with hypertension has no HbA1c in their record within the interval clinicians set, display: *"Ask your doctor whether you need an HbA1c (sugar) test."* Deterministic, record-based, explainable: "the rules decide". HbA1c is a low-cost test, so clinicians are likely to use a low threshold ($\le 3\%$); in that range, testing every patient with high BP is as good as the model. This supports D15 (a rule-based reminder) over a patient-facing ML card.
